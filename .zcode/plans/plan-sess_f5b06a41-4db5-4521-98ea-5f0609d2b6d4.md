## 背景

公共实时估值 API 已全部失效(`fundgz.1234567.com.cn` 301 跳转、`FundMNNewApiEstimate` 返回 404)。当前修复只能拿到上一交易日的确认净值(`FundMNFInfo`)。为恢复"盘中实时估值"功能,自行根据**基金前十大重仓股 + 个股实时行情**计算估算净值。

估算公式(主流基金 App 通用做法):
```
估算涨跌幅 = Σ(重仓股i 今日涨跌幅 × 重仓股i 占净值比)
估算净值 = 上一交易日确认净值 × (1 + 估算涨跌幅/100)
```

## 实施决策(已确认)

- 范围:**所有基金都估**(债基/QDII 也照估,接受误差)
- 模型:**仅前十大重仓**简化版(剩余仓位按 0 贡献,简化实现)
- 行情源:**东方财富 `push2.eastmoney.com`** 批量股票接口(实测可用,JSON 格式,与主源同厂商)
- 集成点:**Option (a)** — 在 `FundViewModel.refresh()` 拿到 NAV 数据后做第二趟估算注入(不嵌入 `FundService`,保持职责分离)

## 新增 3 个服务文件(放在 `FundBar/Services/`)

### 1. `HoldingsService.swift` — 获取并缓存基金重仓股

```swift
final class HoldingsService {
    static let shared = HoldingsService()
    private let session: URLSession  // 复用 FundService 风格(10s/15s timeout)
    
    struct StockHolding: Codable {
        let code: String        // GPDM  股票代码
        let name: String        // GPJC  股票名称
        let weight: Double      // JZBL  占净值比(%)
        let marketCode: String  // NEWTEXCH 市场代码(1=沪,0=深,116=港)
    }
    
    // 内存缓存 + 持久化,key=基金代码,TTL=7天(季报数据)
    private var cache: [String: (holdings: [StockHolding], date: Date)] = [:]
    private let cacheKey = "fund_holdings_cache_v1"  // UserDefaults 持久化
    
    func getHoldings(fundCode: String) async -> [StockHolding]
    // 批量获取(并发,每个基金一次请求,带缓存)
    func getHoldings(for fundCodes: [String]) async -> [String: [StockHolding]]
}
```

- 接口:`FundMNInverstPosition?FCODE=\(code)&deviceid=1&plat=Android&appType=ttjj&product=EFund&version=6.2.0`
- 解析 `fundStocks[]` → `[StockHolding]`,把 `NEWTEXCH`(116/1/0)映射成东方财富 secid 前缀
- 缓存策略:内存字典 + UserDefaults 持久化(参照 `watchedFunds` 的 didSet 模式),TTL 7 天;季报披露期(1/4/7/10 月)可更激进刷新
- 拉取失败/无重仓股(纯债基金)→ 返回空数组,估算跳过

### 2. `StockQuoteService.swift` — 批量获取个股行情

```swift
final class StockQuoteService {
    static let shared = StockQuoteService()
    private let session: URLSession
    
    struct Quote {
        let secid: String       // 如 "1.600519"
        let price: Double       // f43 现价(需 ÷100 或按精度处理)
        let changePercent: Double  // f170 涨跌幅 %
    }
    
    /// 批量查,一次请求拉所有股票
    func fetchQuotes(secids: [String]) async -> [String: Quote]
}
```

- 接口:`https://push2.eastmoney.com/api/qt/ulist.np/get?fields=f2,f3,f12,f14&secids=1.600519,0.000001,116.00700`
- 字段映射:`f2`=现价、`f3`=涨跌幅(×100,需 ÷100)、`f12`=代码、`f14`=名称
- **不缓存**(行情是实时数据,每次刷新都要新拉)
- 返回字典 `[secid: Quote]`,方便估算时按 secid 查找

### 3. `EstimateService.swift` — 估算编排

```swift
final class EstimateService {
    static let shared = EstimateService()
    
    /// 对一批 Fund 注入本地估算的 gsz/gszzl,返回更新后的数组
    func applyEstimates(to funds: [Fund]) async -> [Fund]
}
```

流程:
1. 收集所有 fund 的 fundcode → `HoldingsService.getHoldings(for: codes)`
2. 汇总所有 holdings 的 secid(去重)→ `StockQuoteService.fetchQuotes(secids:)`
3. 对每只 fund,用公式算出估算涨跌幅 / 估算净值
4. 用 memberwise init 重建 `Fund`,注入 `gsz`/`gszzl`(`%.4f` / `%.2f` 精度,对齐 `syncConfirmedNav` 现有格式)
5. 同时更新 `gztime` 为当前时间 `yyyy-MM-dd HH:mm:ss`(保证 NotificationService 去重 key 反映估算更新)
6. **失败兜底**:任何环节出错(无重仓股、行情拉取失败、计算异常)→ 返回原 fund 不动(UI 自然回退到 `FundMNFInfo` 的净值兜底)

### 5. `FundBar/ViewModels/FundViewModel.swift` — 在 refresh() 注入估算

在现有 `refresh()` 的 `self.funds = result` 前(FundViewModel.swift:739 前),插入:
```swift
// 盘中时段 + 净值未确认 → 注入本地估算
if isTradingTime {
    result = await EstimateService.shared.applyEstimates(to: result)
}
```

- **仅在 `isTradingTime` 触发**(FundViewModel.swift:373 已有此属性,周一到周五 9-11:30/13-15)

## 不做的事(明确边界)

- ❌ **不重构 UI**(不加"本估"标记,不改颜色;现有 `估 X.XXXX` 文案直接复用)
- ❌ **不动现有 `FundService` 的主源/fallback 逻辑**(刚改好的,不碰)
- ❌ **不动持久化路径**(`watchedFunds` 一行不碰)
- ❌ **不做多指数加权**(用户已选简化版,前十大重仓够用)
- ❌ **不做债基/QDII 特殊处理**(用户已选照估)
- ❌ **不缓存股票行情**(实时数据,缓存无意义)

## 精度预期(提前对齐)

- 主动权益基金:误差通常 ±0.5%(前十大重仓覆盖 40-60% 仓位,剩余按 0 贡献)
- 指数基金:误差 ±0.2%(持仓透明)
- 债券基金:**误差较大 ±2%+**(重仓股占比低,债券部分无法估)
- QDII:**误差最大**(海外时差 + 汇率,A 股交易时段估的是海外昨天的数据)

## 验证方式

1. Xcode Run,进入交易时段(周一到周五 9:30-11:30 或 13-15)
2. 基金列表显示 `估 X.XXXX` + 涨跌幅(不再是上一交易日的旧值)
3. 对比同一只基金在天天基金 App 的官方估值(误差应在上述范围内)
4. 盘外时段:不显示估值,回退到上一交易日净值(现有逻辑)

## 风险评估

- **数据风险:零**。只改 `funds`(运行时 API 数据),不碰 `watchedFunds`(本地持仓)。
- **回归风险:低**。估算失败时原样返回 fund,UI 回退到 `FundMNFInfo` 的净值兜底,不会比现状更差。
- **性能风险:中**。每次 refresh 多 2 个网络请求(重仓股走缓存,股票行情必拉)。17 只基金 ≈ 170 只股票,一次批量请求即可,可控。
- **精度风险:已知**。债基/QDII 误差大,但用户已确认接受。
- **接口二次失效风险:中**。股票行情接口比基金估值接口稳定得多(东方财富核心业务),但若失效,有 fallback(原样返回 fund)。
